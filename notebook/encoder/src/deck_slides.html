What goes in, what comes out

An encoder reads all its tokens at once — a sentence, or an image cut into patches — and a layer turns T token vectors of width d into T new ones of the same width.

T = tokens (512 for BERT, 197 patches for ViT-B/16) · d = model width (768 for BERT-base, 4096 for an 8B model) · h heads of d/h each · ffn = the FFN's inner width, usually 4·d.

Two halves, each added back onto x: attention lets tokens look at each other; the FFN works on each token alone.

The layer, one operation per step

4 tokens, d = 8, 2 heads, ffn = 16: 664 parameters, 5280 operations. The run ends with the walk checked against the same layer computed token by token.

Attention: the only place tokens mix

Q, K, V are three plain matmuls, [T, d] × [d, d], the same weights for every token — the matmul deck's subject.

Attention mixes tokens: each output row is a weighted average of all the V rows — the attention deck's subject, once per head.

The output projection mixes the heads back, and the residual add keeps x: the layer only adds a correction.

The FFN: each token on its own, and the biggest part

Widen d → ffn, an activation element by element, narrow back. Gated forms (SwiGLU, GeGLU) add a third matrix.

Where the parameters are

A BERT-base layer: the four projections hold 4·d², the FFN 2·d·ffn = 8·d² — two thirds of the layer. Step to price each operation on an A100.

More tokens: attention grows as T²

Every matmul grows with T; attention with T². The same BERT layer at more and more tokens.

Same layer, three chips: the bound flips

A projection at 512 tokens does about 220 operations per byte: above A100's ridge (153) — compute-bound; below H100's (295) — memory-bound; far below an edge NPU's (6168).

Norms, activations, residuals: memory-bound everywhere

A few operations per number read and written: 1 to 4 OP per byte, against ridge points in the hundreds.

So on every chip they wait on memory — a small share of the time, but pure overhead.

Real kernels fuse them into the neighbouring matmul: the data is already on chip, and the extra pass over memory disappears.

Batch: more rows, the same weights

B sentences are B·T rows for every projection and FFN — the weights are read once and used B times more, so their OP per byte rises. Each sentence still attends only to itself.
